## 무엇을 해결하는가

함정 감지가 부분문자열 매칭이라 한국어에서 정밀도 한계가 명확했다.
`'600'`이 `"3600만원"` 안에서 걸리고, `'감면'`·`'부분'` 같은 짧은 말이
무관한 질의를 끌어왔다. 주제어를 아무리 다듬어도 남는 구조적 문제다.

이 계층은 **HCX가 실제 법령 조문을 보고 함정 적용 여부를 판정**하게 하되,
판정의 근거가 조문에 글자 그대로 실재하지 않으면 코드가 그 판정을 폐기한다.

```
HCX 판정 ──> 인용 검증 ──> 통과분만 반영
                  │
                  └─ 실패: 조문 창작 · 내용 창작 · 의역 · 짧은 인용
                     → 폐기하고 think_trace에 사유 기록
```

**지어낸 근거는 구조적으로 답변에 도달할 수 없다.** 검증을 통과한 판정만
남으므로, 남은 것은 전부 실재하는 조문 문자열에 뒷받침된다.

## 설계 제약과의 관계

| 제약 | 어떻게 지켰나 |
|---|---|
| LLM 호출 3개소 (L1·L5'·L6) | 함정 판정을 **기존 L6 감사 호출 안에** 접었다. 호출 수 변화 없음 |
| 판단은 코드 | 최종 반영 여부는 코드(`citation_guard`)가 결정한다. HCX는 후보를 낼 뿐 |
| 답변 생성은 HCX 전용 | 이 계층은 답변 문장을 만들지 않는다 |
| 제공 문서 근거 | 법령은 **내부 검증 전용**. `retrieved_context`에는 제공문서만 실린다 |

## 절차

### 1. 법제처 OPEN API 신청

<https://open.law.go.kr> 에서 OPEN API 활용을 신청한다. 발급되는 `OC` 값은
신청한 이메일의 `@` 앞부분이다.

### 2. 수집 (배포 서버에서)

첫 실행은 **반드시 `--dry-run`** 으로 파싱 결과를 눈으로 확인한다.

```bash
python -m app.law.crawler --oc <OC> --dry-run
```

조문 수와 표본 원문이 정상으로 보이면 저장한다.

```bash
python -m app.law.crawler --oc <OC> --out data/law/articles.json
```

> ⚠️ 파서는 공개된 응답 구조에 맞춘 픽스처로만 검증했다. 개발 환경에서
> `law.go.kr` 이 egress 정책으로 차단돼 실 API 응답을 받아보지 못했다.
> 구조가 다르면 조용히 빈 결과를 내지 않고 예외를 던지도록 해 두었으므로,
> `--dry-run` 이 실패하면 그 메시지를 보고 파서를 맞추면 된다.

### 3. 앵커 확인

규칙별 근거 조문 후보를 본다.

```bash
python -m app.law.anchors --propose
```

**확인한 것만** `app/law/anchors.py` 의 `ANCHORS` 에 등재한다.
추측으로 채우지 말 것 — 틀린 조문 번호는 틀렸다는 걸 알 방법이 없다.
등재 후 실재를 재확인한다.

```bash
python -m app.law.anchors --verify
```

### 4. 배포

`data/law/articles.json` 은 코퍼스와 같은 방식으로 볼륨 마운트하거나
저장소에 커밋한다. 파일이 없으면 법령 근거 판정만 꺼지고 나머지는
그대로 동작한다 — 기동을 막지 않는다.

## 권한 모드

`apply_to_traps(..., authority=)` 로 고른다.

| 모드 | 동작 | 언제 |
|---|---|---|
| `citation_verified` (기본) | 검증된 판정에 한해 함정 **추가·제거 모두** 허용 | 수집·앵커 확인이 끝난 뒤 |
| `escalate_only` | 추가만 허용, 제거 기각 (단조성 유지) | 수집이 불완전한 동안 |

두 모드 모두 검증 실패 판정은 애초에 도달하지 못한다.

## 이 계층을 고칠 때 지킬 것

- **인용 대조를 느슨하게 만들지 말 것.** 유사도·어간 비교로 바꾸면 의역이
  통과하고, 그 순간 차단 기능이 사라진다. 엄격해서 정탐을 놓치는 것은
  안전한 실패(결정론적 판정으로 복귀)지만, 느슨해서 오탐을 통과시키는 것은
  안전하지 않다.
- **조문 원문을 가공하지 말 것.** 요약·정규화 저장 모두 금지. 대조의
  기준이 되는 텍스트다.
- **앵커를 기억으로 채우지 말 것.** `tests/test_law_grounding.py` 가
  이를 감시한다.

## 저촉 판정 — 답변이 조문에 어긋나는가 (2026-09-04 신설)

위 절의 "함정 판정"은 **"이 함정이 이 질의에 적용되는가"**를 묻는다.
여기 저촉 판정은 **"이 답변이 조문에 어긋나는가"**를 묻는 완전히 다른
질문이다 — 묻는 것이 다르므로 게이팅 조건도 다르다.

| 갈래 | 묻는 것 | 게이팅 | 판정 반영 |
|---|---|---|---|
| 함정 판정 (위 절) | 이 **함정**이 이 질의에 적용되는가 | `trap_ids`(L2 함정감지 의존) | `trap_ids` 조정 → 결정론적 감사 재실행 |
| **저촉 판정** | 이 **답변**이 조문에 어긋나는가 | 조문만 있으면(게이팅 없음) | 검증 통과분을 REVISE로 **상향만** |

### 왜 게이팅이 다른가

함정 판정은 `_law_context()`가 L2가 감지한 `trap_ids`로 관련 조문을
걸렀다. 그런데 298건 실측에서 **질의의 55%(함정 0건 49.0% + 앵커
미등재 6.0%)가 조문을 한 줄도 못 보고 지나갔다.** 함정이 없으면
법령 계층 전체가 죽는 구조였던 것이다.

저촉 판정은 `law/relevance.py`의 `_law_relevance()`가 **답변이 실제로
쓴 용어**로 관련 조문을 고른다 — L2·`trap_ids`와 무관하다. 그래서
함정이 하나도 없는 질의에서도 답변–조문 대조가 돈다(mock 60건 표본에서
93.3%가 조문 선택 전제조건 충족).

### 세 겹 차단선

저촉으로 **채택**되려면 세 조건을 전부 통과해야 한다. 하나라도 실패하면
폐기하고 결정론적 판정은 그대로 유지된다(오탐이 미탐보다 나쁘므로,
애매하면 채택하지 않는 쪽으로 기운다).

1. **조문 인용(`quote`) verbatim** — 공백만 정규화해 대조. `MIN_QUOTE_CHARS=12`
   미만이면 폐기.
2. **답변 문장(`answer_span`)도 verbatim** — 지목한 답변 문장이 실제
   답변에 글자 그대로 있어야 한다. 이게 없으면 모델이 실재 조문을
   정확히 인용해 놓고 **답변이 하지도 않은 말**을 저촉이라고 지어낼 수
   있다.
3. **`corpus_supports_span` — 제공 문서가 최종 근거, 법령은 보조**
   (과제 안내 6페이지: "제공자료가 최종근거이며, 외부정보는 보조로만
   쓰고 상충 시 제공자료 우선"). 지목된 답변 문장이 제공 문서와도
   맞는지를 함께 본다:

   | 답변이 제공 문서와 | 답변이 법령과 | 처리 |
   |---|---|---|
   | 맞다 | 어긋난다 | **폐기** — 제공 자료 우선 |
   | 안 맞다 | 어긋난다 | **채택** — 명확히 수정(REVISE) |
   | 근거 0건 | 어긋난다 | 채택 (뒷받침할 문서가 없음) |

   뒷받침 판정은 결정론적이다 — ① 근거에 그대로 있는가 ② 문장의
   수치가 전부 근거에 있는가 ③ 수치 주장이 없고 같은 주제의 근거가
   있는가. 판정 로직은 `verify_conflicts`가 한다 — 프롬프트 지시만으로
   두지 않는다("판단은 코드, 문장은 LLM").

### 판정은 상향 전용이다

함정 판정은 감사의 **입력**(사실)을 바꾸므로 추가·제거가 모두 가능하다.
저촉 판정은 **판정 자체**라서 다르다 — 여기서 LLM이 심각도를 내릴 수
있으면 L6의 단조성(권한 계층: LLM은 심각도를 올릴 수만 있음)이 무너진다.
"조문상 문제없음"은 아무것도 무르지 못한다. 채택되면 **REVISE**로 낸다
(DOWNGRADE가 아니다 — 조문 인용이 붙은 구체적 시정 지시를 만들 수
있으므로 등급만 낮추고 지시를 버리면 안 된다).

### 호출 횟수는 늘지 않는다

함정 판정·저촉 판정 둘 다 **L6 의미 감사 한 호출**에 함께 실린다. 다만
페이로드는 커진다(조문 4건이 실릴 때 697자 → 3,772자 실측) — 그래서
`BUDGET_L6`을 8.0 → 10.0으로 올렸다.

### 운영 확인

- **가동 여부**: `GET /health`의 `law.conflict_check_active` — 저촉
  검사는 앵커가 아니라 **수집본 자체**만 있으면 돌므로 `law.active`와
  조건이 다르다(앵커는 함정 판정 전용). 하나로 합치면 저촉 검사가
  죽어도 `active=true`로 보인다.
- **못 한 것과 대상이 없던 것 구분**: 조문이 하나도 안 실리면
  `법령저촉/NOT_RUN`, 대조했는데 지적이 없으면 `법령저촉/NONE`을
  think_trace에 남긴다.
- **미해소 저촉은 Sub-Agent가 받는다** — `detect_anomalies`가
  critical로 감지해 구제 재생성까지 열고, 조문 저촉을 다른 지적보다
  **앞에** 싣는다(목록 한가운데 파묻히면 안 되는 지적이므로).
- **법령 조문은 여전히 내부 검증 전용** — `retrieved_context`에 넣지
  않는다(위 절과 동일 원칙).

### 이 갈래를 고칠 때 추가로 지킬 것

- **조문 선택은 결정론적이다.** `law/relevance.py`가 어느 조문을 볼지
  실행마다 달라지면 같은 질의가 매번 다른 검사를 받는다. 점수 동률은
  조문 참조 문자열 순으로 깬다.
- **⚠️ 모듈 최상단에서 `get_store`를 이름으로 묶지 말 것** — 처음
  import된 순간의 저장소를 끝까지 물게 된다.
- **답변 용어와 조문 용어는 같은 방식으로 뽑을 것** — 한쪽은 토큰화,
  다른 쪽은 부분문자열이면 반드시 어긋난다(인용 기준과 매칭 기준을
  다르게 두는 것과 같은 함정).
- **L2(함정 감지)를 걷어내면 함정 판정만 죽는다 — 저촉 판정은 살아
  있다.** 두 갈래의 독립성이 이 개편의 핵심이므로, 리팩터링 시 서로
  다시 결합시키지 말 것.
